# ตรวจระบบเทียบโจทย์, ขอบเขต MVP และ User Journey

ตรวจเมื่อ 16 ต.ค. 2569 จากโค้ดในรีโพนี้ ไฟล์โจทย์ `Final Project.pdf` และการรันระบบจริง

## สรุป: ระบบมีอะไรเกิน อะไรขาด และปรับอย่างไร

**บอทนี้ช่วยใคร แก้ปัญหาอะไร** — Blinks Bright คลินิกความงามขนาดเล็ก (ข้อมูลจำลอง) 2 สาขา
ลูกค้าส่วนใหญ่ทักนอกเวลาทำการและถามเรื่องเดิมซ้ำ ๆ (ราคา โปรโมชัน สาขา เวลาเปิด มัดจำ การเลื่อนนัด)
บอทตอบจากข้อมูลจริงของร้าน จองคิวและส่งลิงก์มัดจำได้ อ่านรูปสลิป/ป้ายราคา และส่งต่อพนักงานเมื่อเกินหน้าที่
ผู้ใช้หลักคือ **ลูกค้า** (หน้าเว็บ + แชทวิดเจ็ต) ผู้ใช้รองคือ **พนักงาน** ที่ดูแชทและรับช่วงต่อ

**เกิน** — โค้ดเป็นแพลตฟอร์มหลายคลินิก หลังบ้านมี 14 เมนู + system console 3 เมนู มี broadcast, retention automation,
หน้า analytics 2 หน้าที่ซ้อนกัน และ LINE/Messenger ซึ่งโจทย์ไม่ได้ขอ ส่วนเกินทั้งหมดอยู่**ฝั่งพนักงาน**
ลูกค้าไม่เห็นเลย จึงไม่ทำให้ลูกค้าสับสน

**ขาด** — ตัวระบบทำงานครบตามข้อกำหนดเกือบทั้งหมดก่อนเริ่มตรวจแล้ว ที่ขาดคือ**หลักฐานและเอกสาร**
(บันทึกผลทดสอบ, แผนภาพ 2 แบบ, จุดปรับปรุงพร้อมก่อน-หลัง, บทคลิป, บันทึกงานคู่)
ส่วนตัวระบบพบช่องโหว่ 5 จุดจากการรันจริง (ข้อความต้อนรับไม่บอกว่าช่วยอะไรได้, ส่งข้อความไม่สำเร็จแล้วเงียบ,
พูดซ้ำตัวเลขจากรูปที่หลอก, ปฏิเสธต่อราคาแต่ไม่บอกราคาจริง, เอ่ยชื่อบุคคลที่ถูกถามถึง) แก้แล้วทั้งหมด ดู [IMPROVEMENTS.md](IMPROVEMENTS.md)

**ปรับอย่างไร** — ไม่ลบโค้ดที่ทำงานและมีเทสต์อยู่แล้ว (ย้อนกลับไม่ได้ง่ายและไม่ช่วยลูกค้า)
แต่**จำกัดขอบเขตที่นำเสนอ**ให้เหลือเส้นทางที่โจทย์ขอ: แผนภาพ คลิป และเอกสารพูดถึงเฉพาะเส้นทางนั้น (หัวข้อ 2)

## 2. ขอบเขต MVP และการจัดเมนู

**หลักการ** แยกสิ่งที่ลูกค้าเห็นออกจากเครื่องมือพนักงาน ลูกค้าเห็นเพียง 3 หน้า ซึ่งเรียบง่ายอยู่แล้ว
ฝั่งพนักงานเลือก**ซ่อนจากการนำเสนอ**แทนการลบโค้ด เพราะทุกเมนูทำงานและมีเทสต์ การลบจะกระทบ route, `NAV_ROLES`,
เทสต์ และ endpoint ที่ใช้ร่วมกัน (เช่น dashboard ใช้ข้อมูลเดียวกับ analytics) โดยไม่ทำให้ลูกค้าใช้งานง่ายขึ้นเลย

### ฝั่งลูกค้า

| หน้า | การตัดสินใจ | เหตุผล |
|---|---|---|
| หน้าเว็บคลินิก `/` | คงไว้ | ทางเข้าหลัก แสดงบริการ โปรโมชัน สาขา จากข้อมูลจริง |
| แชทวิดเจ็ต | **คงไว้ + ปรับ** | หัวใจของโจทย์ เพิ่มข้อความต้อนรับ ปุ่มลัด error/ลองใหม่ |
| บัญชีลูกค้า `/portal` | คงไว้ ไม่โชว์ในคลิป | ช่วยลูกค้าดูนัดของตัวเอง แต่โจทย์ไม่ได้ขอ (ระบบสมาชิก) จึงไม่ขยายเพิ่ม |

### ฝั่งพนักงาน (`/admin`)

| เมนู | การตัดสินใจ | เหตุผล |
|---|---|---|
| Conversations (การสนทนา) | คงไว้ (หน้าแรกหลังล็อกอิน) | ส่งต่อทีม/รับช่วงจาก AI คือมาตรการความปลอดภัยตามโจทย์ |
| Payments (การชำระเงิน) | คงไว้ | พนักงานตรวจสลิปและกดยืนยันรับเงินที่นี่ บอทยืนยันการชำระเองไม่ได้ |
| Bookings (การจอง) | คงไว้ | ปลายทางของการจองที่บอทสร้าง |
| Treatments, Knowledge | คงไว้ | คือคลังความรู้ของบอท แก้แล้ว reindex อัตโนมัติ |
| Settings (ตั้งค่า) | คงไว้ | เวลาเปิด-ปิดสาขาและคำสั่งเพิ่มเติมของ AI คือข้อมูลร้านที่เจ้าของต้องแก้เองได้ ไม่อย่างนั้นบอทตอบเวลาผิด |
| Customers, Team | คงไว้ | ข้อมูลลูกค้าที่บอทเก็บ / แพทย์ในคลังความรู้ |
| Dashboard (ภาพรวม) | **ซ่อนจากเมนูแล้ว** | แดชบอร์ดยอดขาย โจทย์ไม่ได้ขอ |
| Test Console (ทดสอบระบบ) | **ซ่อนจากเมนูแล้ว** | เครื่องมือนักพัฒนา หลักฐานทดสอบมาจาก `evals/deliverable.py` (API `/api/test/*` ยังอยู่และใช้ในเทสต์) |
| Analytics, Chat Analysis | **ซ่อนจากเมนูแล้ว** | ไม่อยู่ในเกณฑ์โจทย์ และสองหน้านี้ทับซ้อนกัน |
| Broadcast, Retention | **ซ่อนจากเมนูแล้ว (เลื่อนไประยะถัดไป)** | เป็นการตลาดเชิงรุก ไม่ใช่ "ตอบลูกค้าแทนเจ้าของร้าน" |
| System console (หลายคลินิก) | **ซ่อนจากการนำเสนอ** | เกินขอบเขต "ธุรกิจเล็ก 1 ราย" ชัดเจนที่สุด แต่ `clinic_id` อยู่ในทุกตาราง จึงไม่รื้อ |
| LINE / Messenger | **เลื่อนไประยะถัดไป** | ต้องมี tunnel สาธารณะและบัญชีจริง โจทย์ใช้เว็บแชทพอ |

**MVP ที่นำเสนอ** = หน้าเว็บ → แชทวิดเจ็ต (ข้อความ + รูป) → คลังความรู้/เครื่องมือ → การจอง/มัดจำ
\+ กล่องข้อความพนักงานสำหรับรับช่วง ทั้งหมดนี้คือสิ่งที่วาดใน [ARCHITECTURE.md](ARCHITECTURE.md)
ไม่ได้เพิ่ม dashboard ระบบสมาชิก multi-agent หรือระบบหลังบ้านใหม่

**ซ่อนจากเมนูแล้ว:** ภาพรวม, ทดสอบระบบ, Retention, Analytics, Chat Analysis และ Broadcast ถูกเอาออกจาก `NAV`
ใน `web/js/app.js` เมนูหลังบ้านเหลือ 8 รายการ (การสนทนา การจอง แพทย์และทีมงาน ลูกค้า การชำระเงิน ทรีตเมนต์
คลังความรู้ ตั้งค่า) พนักงานเข้าระบบแล้วเจอหน้าแรกที่ตำแหน่งตัวเองเปิดได้ (การสนทนา สำหรับเจ้าของ/ผู้จัดการ/เซลส์/แพทย์)
ถ้าพิมพ์ URL ของหน้าที่ซ่อนตรง ๆ (เช่น `#/dashboard`) ระบบจะพาไปหน้าแรกแทน หน้าจอและ API ยังอยู่ในโค้ด
เอาเครื่องหมาย comment ออกเพื่อเปิดกลับได้

## 3. User Journey

ทุกข้อความด้านล่าง**ใช้งานจริงแล้ว**ในระบบ (ไม่ใช่ข้อเสนอ)

| 📷 ส่งรูป/สลิป | (เปิดหน้าต่างเลือกรูป) |

### ข้อความต้อนรับ

> สวัสดีค่ะ ยินดีต้อนรับสู่ Blinks Bright 🌿 ดิฉันเป็นผู้ช่วย AI ของคลินิก ช่วยได้เรื่อง
> - ราคาและรายละเอียดทรีตเมนต์
> - โปรโมชัน สาขา และเวลาเปิด-ปิด
> - จองคิวและชำระมัดจำ
> - ดูรูปที่ส่งมา เช่น สลิปโอนมัดจำ หรือป้ายราคา (กดปุ่มรูปภาพด้านล่าง)
>
> เลือกหัวข้อด้านล่าง หรือพิมพ์คำถามได้เลยค่ะ ส่วนคำถามเรื่องอาการหรือผลข้างเคียง ทีมแพทย์จะเป็นผู้ดูแลให้นะคะ

### ข้อความแจ้งข้อผิดพลาด

| สถานการณ์ | ข้อความ |
|---|---|
| ส่งข้อความไม่สำเร็จ | ส่งไม่สำเร็จ · **ลองอีกครั้ง** (ปุ่ม) |
| แชตหมดอายุ | แชตนี้หมดอายุแล้ว กรุณากดปุ่มเริ่มแชตใหม่ด้านบน |

### Flow

| สถานการณ์ | เป้าหมายผู้ใช้ | สิ่งที่ผู้ใช้ทำ | สิ่งที่ระบบแสดง/ตอบ | ขั้นตอนถัดไป |
